### A.2 逐 provider 复活判定

**四项全部「复活安全」**——每个 onChanged 都是纯 sync-state 发布，无任何重启/IO/await：

1. **settingsProvider — 复活安全（本 PR 目标）**
   - IsolateSyncSettingsAction（packages/.../actions_sync.dart:56-95）是同步 reduce → `_PublishSyncStateAction`（同文件 :98-127）→ 对 discovery/httpUpload/httpServer 三个 connector 做 null-aware（`?.`）sendToIsolate + 更新父侧 syncState。幂等。
   - 4 字段守卫（settings_provider.dart:23-28）使主题/动画等无关变更早退，零派发。
2. **securityProvider — 复活安全，且顺带修复 release 潜伏 bug**
   - 唯一 dispatch 点即 onChanged（`git grep IsolateSyncSecurityContextAction` 上游仅 security_provider.dart:14）。上游 release 现状：重置安全证书后子 isolate 持旧证书/fingerprint 直到重启（discovery 绑定用 `syncState.securityContext.certificateHash/certificate/privateKey`，上游 discovery.dart:73/76/77）。复活 = 修复。
3. **deviceInfoProvider — 复活安全，且顺带修复 release 潜伏 bug**
   - 唯一 dispatch 点即 onChanged（仅 device_info_provider.dart:28）。上游 release 现状：高级设置里改 deviceType/deviceModel 不同步到 isolate（discovery 宣告用旧 deviceModel/deviceType，上游 discovery.dart:71-72）。逐键触发仅产生廉价 sync 消息（无 rebind），与 debug 现状一致。复活 = 修复。
4. **serverProvider — 复活安全（重点审查项），且顺带修复 release 潜伏 bug**
   - **onChanged 不重启服务器**——它只派发 IsolateSyncServerStateAction（sync 发布，actions_sync.dart:79-127）。任务问的「若重启服务器会否有意外行为」不成立：该路径不存在重启语义。
   - **无双重派发**：startServer 在 `state = newServerState` 之前显式 `_syncServerState(...)`（server_provider.dart:443 辅助、startServer 内 :171 附近调用），故 onChanged 触发时 syncStatePrev == syncStateNext → 早退；start 失败 catch 路径同样显式同步（`_syncServerState(serverRunning: false)`）且 state 保持 null 无通知。
   - **stopServer 是唯一依赖 onChanged 的同步点**：`stopServer()`（:246-253 附近）无显式同步，`state = null` → onChanged → 派发 serverRunning=false。`IsolateHttpServerStopAction`（actions.dart:346-362）只向 server isolate 发 stop 任务、不更新父 syncState。**上游 release 现状：停止服务器后 syncState.serverRunning 恒为 true → discovery isolate 继续应答宣告，广告一个已死的 HTTP 端口**（正是上游 discovery.dart:59-60 注释自述要避免的场景："the answer would advertise an HTTP port that nobody listens on otherwise"；应答开关由 syncProvider 流监听 serverRunning 翻转驱动，上游 discovery.dart:54-57 + :93-95）。复活 = 修复此潜伏 bug。
   - **稳态开销**：每次传输进度事件触发一次 5 元组比较（两个 provider 读 + record 相等），与 debug 今日行为完全一致，可忽略。
   - **边界**：stopServer 后元组取 `settings.alias/port/https` 兜底（onChanged :39-44）——serverRunning=false 时 discovery 不应答宣告，端口字段无消费者；下次 startServer 显式同步正确值。无不一致路径。
   - **detached 交错**：`IsolateDisposeAction`（parent_isolate_provider.dart:99-106）kill isolate 但不清 connector → `_PublishSyncStateAction` 的 `?.` 仍向死端口 send（静默 no-op，见 C-2）。

### A.3 A 节结论

**4/4 复活安全，零回归路径；其中 3 个（security/deviceInfo/server-stop）是上游 release 构建的既有潜伏 bug 被顺带修复**。PR 正文必须诚实披露：bab27003 复活的是**全部四个** provider 的 onChanged，不止 settings——建议作为「附带修复」正面陈述（附上表），而非仅提 settings。这同时是回答上游 reviewer「为什么动 init.dart」的最强论据。
