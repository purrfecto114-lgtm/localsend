## 1. Strengths

1. **机制选型正确**：MulticastLock 正是 Android 官方对「WiFi 省电过滤丢弃非本机寻址组播包」的平台答案；AOSP `WifiManager.java` 类注释（main 分支 :8405-8411）几乎逐句对应 commit message，说明作者做了功课。这补上了 round-1 R-7 明确点名的缺口（「MulticastLock 仍全仓缺失，F4 只修 socket 死亡半边」——接收半边现被解锁）。
2. **生命周期粒度正确**：锁随 Activity 存续 = discovery 存续（discovery isolate 挂在主 engine 下，见 §4.1/§4.3），含后台 FGS 接收时段；比 onResume/onPause 粒度更对（后者会切断后台传输期间的 peer 发现）。

**I-1. `getSystemService(WIFI_SERVICE)` 可返回 null → 未判空 cast 在无 WiFi 硬件设备上启动即崩（NPE in onCreate）**
- File: `app/android/app/src/main/kotlin/org/localsend/localsend_app/MainActivity.kt:58`
- 证据链（三环互证）：
  1. **AOSP 源码**：Android 13 起 `WifiFrameworkInitializer.registerServiceWrappers()` 的 lambda 对 `!hasSystemFeature(PackageManager.FEATURE_WIFI)` 的设备 **return null**（main 分支 :84-87；android-13.0.0_r1 :80-83）。Android 12 及以前无此判空（android-12.0.0_r1 :71-79，恒返回实例）。故崩溃面 = **Android 13+ 且无 `android.hardware.wifi` 特性**的设备（纯以太网 Android TV 盒子/机顶盒、部分车机、数字标牌——LocalSend 明确支持 leanback TV，manifest:30/64）。
  2. **字节码**：编译产物 `MainActivity.class` 常量池含 `"null cannot be cast to non-null type android.net.wifi.WifiManager"` + `checkNotNull`（javap 不可用，以 strings 提取；另用独立 Probe.kt 复刻同一 cast 也生成同串）——kotlinc 2.2.0 对 @Nullable 返回值的 `as WifiManager` 插入显式判空，**cast 处直接抛 NPE**。
  3. **运行时实验**：`null as java.util.zip.CRC32`（平台类型同构场景）实跑输出 `CAUGHT: java.lang.NullPointerException: null cannot be cast to non-null type java.util.zip.CRC32`。


## I-1 — FIXED（MainActivity.kt:56-65）

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    // Devices without Wi-Fi hardware (e.g. Ethernet-only TV boxes) have no
    // Wi-Fi multicast filtering; getSystemService returns null there since API 33.
    val wifiManager = applicationContext.getSystemService(Context.WIFI_SERVICE) as? WifiManager ?: return
    multicastLock = wifiManager.createMulticastLock("LocalSendDiscovery").apply { ... }
}
```

控制流逐路径核验：
1. **正常设备**：非 null → 持锁，与 round-3 已验证行为一致。
2. **无 WiFi 硬件 + API 33+**：`getSystemService` 返回 null（round-3 AOSP 证据：android-13.0.0_r1 WifiFrameworkInitializer:80-83）→ `as?` 得 null → `?: return` → onCreate 提前返回。`return` 只跳过锁块——它是方法最后一段语句，`super.onCreate`（引擎初始化）已先行；Activity 生命周期照常走 onStart/onResume。**不崩**。
3. **无 WiFi 硬件 + API <33**（12.0/12.1 实证无特性检查，返回实例）：acquire() binder 调用对无特性设备成功（锁为无害 no-op）——不崩，且与 FGS WifiLock 既有行为一致（无历史崩溃报告佐证）。
4. **ROM wifi 服务异常（binder 未注册/服务被禁用）**：`getSystemService` 返回 null → 同路径 2 被覆盖。**比仅 API 33 特性检查更宽**——任何返回 null 的 ROM 怪癖都安全。
5. **binder 死亡（system_server 崩溃中）**：acquire() 的 RemoteException→RuntimeException 未 try/catch——但这是修复前就存在的全设备行为（非回归），且 system_server 死亡为系统级灾难状态；FGS 的 WifiLock 同款。Info 级，不阻断。
6. **onDestroy 在 multicastLock==null 时**：`multicastLock?.takeIf{...}?.release()` 安全调用链对 null 短路为 no-op，`multicastLock = null` 与 `super.onDestroy()` 照常执行。✓
