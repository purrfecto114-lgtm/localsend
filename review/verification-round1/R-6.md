**证据**:

```dart
if (checkPlatform([TargetPlatform.iOS, TargetPlatform.android])) {
  // The OS may have invalidated the sockets of the suspended app without any error ever reaching the accept loop.
  ref.notifier(serverProvider).ensureRunning();
}

  // The multicast sockets die the same silent way but cannot be probed, so always rebind them.
  ref.redux(parentIsolateProvider).dispatch(IsolateDiscoveryRestartAction());
}
```

server_provider.dart 同 commit 新增 `ensureRunning()`：用 **loopback TCP probe（2s timeout）** 检测 server 死活，探测失败才重启（`_probeInFlight` 防重入）。

**设计意图解读（有据）**：上游对"resume 恢复"做了两层区分——
1. **可探测的（TCP server）**：iOS+Android 都用**探针**，避免无条件重启；
2. **不可探测的（multicast discovery）**：**仅 iOS** 无条件重绑，注释明说 "cannot be probed" —— 即"socket 被 OS 静默回收"被视为 iOS 挂起模式的死亡方式，Android 被有意排除。

**与补丁的关系** [Important]：补丁把无条件 discovery 重绑扩展到 Android，是对 63efbe6b 明确设计决策（iOS-only gate）的**方向性偏离**——补丁 commit message 与 main.dart 注释都如实自曝了这一点（"Note for upstream discussion: … a probe-based rebind … would be the alternative"）。且补丁自己在 `FetchLocalIpAction` 里已实现"IP 集合变化才重绑"，而 resume 时基线本来就会 dispatch `InitLocalIpAction → after() → FetchLocalIpAction`（基线 local_ip_provider.dart:60-64 证实），即 **Android resume 时"网络变了"的场景已被 2c 覆盖**；main.dart 的 Android 扩展只额外覆盖"同网络但 socket 静默死亡"——那正是上游注释里 iOS 特有、Android 被排除的死亡模式。→ 将来上游 PR 时这是最可能被维护者 push back 的一条（详见 §7 建议）。
